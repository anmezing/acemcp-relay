# Durable platform configuration saves

The admin save endpoint validates provider connectivity before accepting work. LCE then stores an immutable encrypted configuration snapshot with its base configuration identity and operation UUID. Preparation does not change live configuration or clear indexes. Relay stores only the UUID, section, reset flag and task state; provider keys are never persisted in Relay jobs.

HTTP 202 means a task was accepted, not that saving completed. Query `GET /internal/platform-model-config?operation=<UUID>` or `?operation=latest` using the console authentication token. The admin UI polls these states and restores pending work on reload. The existing configuration GET remains available independently of the task worker. Closing the browser does not cancel accepted work.

For embedding resets, admission takes the same database advisory lock as index lease acquisition and rejects active index leases or root deletions. The durable task then prevents new index leases and deletion admission across Relay processes. A background worker commits LCE with the original operation UUID. LCE atomically records the receipt with its configuration update, root removal, projection tasks and embedding-cache removal. The worker then commits Relay cleanup and its success marker in one transaction. A crash between these commits retains the fence and replays the LCE receipt; it never repeats a completed reset against subsequently recreated roots.

The worker has a 400-second execution budget, a 15-minute crash-recovery claim and five automatic attempts with exponential backoff. Unknown outcomes remain `running`. Exhausted attempts set `recovery_required=true` and retain the embedding fence. After repairing the dependency, POST `{ "action":"recover", "operationId":"<original UUID>" }` to resume the same operation. The console exposes this action. Do not manually delete a pending task or mark it terminal to unlock indexing.

LCE rejects a prepared operation durably if its base configuration changed or its preparation is older than seven days. This proves a delayed duplicate cannot apply it. Relay may then mark it rejected without clearing local indexes, and the admin can validate a fresh request. Maintenance clears encrypted snapshots from expired preparations in bounded batches; completed and rejected receipts retain only metadata/results. Receipts do not expire because replay safety must survive arbitrarily late callers. A preparation that never reached Relay is harmless and expires by the same rule.

Deploy the matching LCE protocol/migration 22 before Relay and the frontend. Do not rotate the platform configuration encryption secret while prepared operations depend on it without a planned migration of both live and prepared encrypted data. Restore both databases consistently, preserving operation receipts and unfinished fences. No deployment or production migration was performed as part of these source changes.

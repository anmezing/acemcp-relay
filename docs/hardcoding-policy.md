# 硬编码治理策略

本仓库把常量分为三类：

1. **协议与安全不变量**：MCP 协议版本、工具名、响应 schema、租户断言版本、最小密钥长度等必须与其他仓库或安全模型一致，保留为代码常量，并由契约测试覆盖。
2. **产品标识与领域枚举**：包名、服务名、状态值、角色值、数据库字段语义等属于产品契约，集中在拥有该契约的模块中，不通过部署配置随意改写。
3. **运行策略**：地址、超时、重试窗口、任务租约、文件/请求上限、缓存 TTL、连接池、调度周期和内存容量必须从环境变量加载。Relay 进程默认值集中在 `runtime_policy.go`，包括 HTTP/数据库/Redis 地址、数据库连接池、鉴权与模型配置缓存、配额缓存、调试捕获、索引失败记录保留和索引操作租约；部署层默认值只能出现在 `deploy/` 的具名模板或脚本策略中，并且必须可由环境覆盖。无效值记录告警并安全回退。
4. **安全时效不变量**：租户断言的短时有效窗口由 `tenant_assertion.go` 中具名的 `tenantAssertionTTL` 单点拥有。它限制被窃取断言的重放窗口，不作为普通部署开关开放；修改时必须经过安全评审并更新定向测试。

新增运行策略时应同时更新：

- `runtime_policy.go` 的默认值、变量、加载与关系校验；
- `.env.example`；
- `deploy/docker-compose.yml`；
- `README.md` 的运行时策略表；
- 至少一个验证解析或跨字段约束的测试。

用户可见错误和文档不得把可配置上限描述成服务端永远固定的数字，也不得把恢复流程绑定到某个编辑器、插件或包管理器。协议中的固定标识可以展示，但应解释它是契约，而不是部署策略。


部署文件也属于全局硬编码审查范围：

- `deploy/nginx.conf.template` 不包含真实域名、证书路径、上游地址、上传大小或代理超时；这些值由 `deploy/nginx.env` 显式提供并经渲染器校验。
- `deploy/deploy.sh` 不假设仓库绝对位置或固定兄弟目录，仓库路径、分支与版本均允许 `DEPLOY_*` 覆盖。
- `deploy/tune-host.sh` 中的主机容量是具名、可覆盖、带关系校验的运维基线。
- `deploy/.env.example` 必须覆盖 `docker-compose.yml` 引用的所有变量，公网 origin 不得回退到产品历史域名。
